relops runs scripts from mozilla-platform-ops repositories and personal forks. No manual clones or branch switching. Push a branch, send a coworker one command.

relops --owner aerickson --ref 022526-tool_tweaks android-tools/worker_health/replay_tc_pool.py --help
Install relops ↓

01install

Install in four steps.

You need git, SSH access to the repository, and the tool's interpreter. Python projects with a Pipfile also need pipenv on your PATH. You do not need Go. Downloads on this Quick site require Mozilla SSO in your browser.

1download for your platform

PlatformDownload
macOS · Apple siliconrelops-darwin-arm64
macOS · Intelrelops-darwin-amd64
Linux · arm64relops-linux-arm64
Linux · amd64relops-linux-amd64

Choose your CPU architecture explicitly. SHA-256 checksums are published with every build. Windows isn't supported.

2verify and install the file you downloaded

Run these in the directory where you saved the download. The checksum command must report OK before installing.

printf '%s %s\n' '__RELOPS_SHA_DARWIN_ARM64__' 'relops-darwin-arm64' | shasum -a 256 -c -
mkdir -p "$HOME/.local/bin" && install -m 755 relops-darwin-arm64 "$HOME/.local/bin/relops"

Make sure ~/.local/bin is in your PATH. On macOS you may need to allow the binary in System Settings → Privacy & Security the first time.

3check repository access

git ls-remote git@github.com:aerickson/android-tools.git HEAD

This checks access for the example above. Use your tool's owner and repository when running something else.

4confirm it works

relops --version

Expected: relops {{RELOPS_VERSION}}. Then try the example command above; it prints the replay tool's help.

02usage

Your branch. One command.

Use --owner for a personal fork; the default is mozilla-platform-ops. Launcher options go before repo/path. Everything after it goes to the tool.

The tool starts in your current directory, so relative inputs and outputs behave like local commands. Use --cwd repo if it needs its repository root.

The default runner honors shebangs and detects Python scripts. For Python projects with a committed Pipfile.lock, installed Pipenv prepares and caches runtime dependencies automatically. No outer pipenv run is needed. An explicit --runner python3, bash, or sh overrides detection.

Online runs fetch the latest branch or tag. Every run reports the exact commit on stderr and uses its own temporary checkout. Push your changes first; use a full commit SHA with --ref for an exact revision. --offline requires cached code and an already-prepared environment.

Tools run with your normal permissions. Dev dependencies, submodules, and Git LFS downloads are not installed automatically. Files written into the temporary checkout are removed at exit; files in your current directory stay there.
