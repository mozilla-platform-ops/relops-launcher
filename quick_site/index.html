02beyond the catalog

Share your latest tool. Easily.

Run a tool straight from a repository or branch with relops repo.

Place relops options before the repository or script path; arguments after it go to the tool.

Run an organization tool

relops repo REPO/path/to/tool.py --help

Replace REPO/path/to/tool.py with your script. The default owner is mozilla-platform-ops.

Run from a personal fork

relops repo --owner YOUR_USERNAME --ref my-feature REPO/path/to/tool.py --help

Replace the owner, branch, and script path with your fork's details.

Share your pushed branch

relops repo --ref my-feature REPO/path/to/tool.py

Replace the branch and script path, then send the command to a coworker.

Same command. Latest code. Each online run fetches the latest revision of the selected branch or tag. Use a full commit SHA to run a fixed revision.

Pass a local file to a tool

relops repo REPO/path/to/tool.py ./hosts.csv

Use a tool that accepts a file argument. ./hosts.csv resolves from your current directory.

Run from the repository root

relops repo --cwd repo REPO/path/to/tool.py

Use this for tools that expect repository-relative files. By default, tools run in your terminal's current directory.

When you need more control

Python and runners

Usually, just run the script. Relops follows its shebang or detects Python automatically.

For Pipenv or uv projects, install pipenv or uv first. Relops uses the committed lockfile to prepare and cache runtime dependencies. No outer environment command is needed.

relops repo --runner python3 REPO/path/to/tool.py

An explicit runner uses your own environment and skips automatic project setup. You can also choose bash or sh.

Revisions and offline use

Online runs fetch the latest branch or tag and print the exact commit on stderr. To share a fixed revision, pass a full commit SHA with --ref.

relops repo --offline --ref my-feature REPO/path/to/tool.py

Run that revision online first. Offline use needs cached code and an already-prepared environment.

Permissions and output files

Tools run with your normal permissions. Save outputs in your current directory to keep them; the temporary repository checkout is deleted when the tool exits.

Dev dependencies, submodules, and Git LFS downloads are not installed automatically.

03manual installation

Install at your own pace.

Already installed? You're ready to run tools. For individual installation steps, start here. No Go or Quick CLI needed.

  1. 01download

    PlatformDownload
    macOS · Apple siliconrelops-darwin-arm64
    Linux · amd64relops-linux-amd64

    Download in your browser using Mozilla sign-in. Save to ~/Downloads; if you use another folder, change that path in the commands below.

    macOS signing and first run

    {{RELOPS_MACOS_STATUS}}

    Follow any first-run approval prompt in System Settings → Privacy & Security.

    Downloads are available for macOS Apple silicon and Linux amd64 only.

  2. 02verify

    Check the downloaded file. Continue only when the result says OK.

    (cd "$HOME/Downloads" && printf '%s %s\n' '{{RELOPS_SHA_DARWIN_ARM64}}' 'relops-darwin-arm64' | shasum -a 256 -c -)

    All release checksums

  3. 03install

    Put the verified file in ~/.local/bin.

    mkdir -p "$HOME/.local/bin" && install -m 755 "$HOME/Downloads/relops-darwin-arm64" "$HOME/.local/bin/relops"

    Add it to this terminal's PATH and check the version. Expected: relops {{RELOPS_VERSION}}.

    export PATH="$HOME/.local/bin:$PATH" && relops --version

    For future terminals, add export PATH="$HOME/.local/bin:$PATH" once to ~/.zshrc (zsh) or ~/.bashrc (bash).

  4. 04ready

    You're ready to run tools. Each tool may need its own interpreter, credentials, or other command-line utilities; check its documentation for prerequisites.

    Python projects with a Pipfile need pipenv on your PATH; locked uv projects need uv.
