01how it works

Four steps. You never see three of them.

1

Fetch

Every online run fetches first, using your own git and SSH. Objects are cached, so it is never a fresh clone.

2

Resolve

Branch, tag, or full SHA becomes one exact commit. Missing or ambiguous refs fail loudly. Stale code never runs quietly.

3

Isolate

A fresh detached worktree per invocation. Two people running the same SHA never see each other's files.

4

Exec

Your args, stdin, stdout, exit code and Ctrl-C pass straight through. Then the worktree is deleted.

Every run prints one provenance line to stderr: repo, requested ref, full SHA, online or cached. Stdout belongs to the tool. Your captured logs always say exactly which code ran.

02the contract

Small surface. Boring on purpose.

relops [launcher-options] <repo>/<path> [tool-arguments...]

The first positional argument ends launcher parsing. Everything after it, including --help and --ref, goes to your tool untouched.

OptionMeaning
--ref VALUEBranch, tag, or full commit SHA. Omit for the remote's real default branch.
--runner auto|python3|bash|shHow to execute. auto needs an executable shebang. No extension guessing.
--cwd repo|callerWhere the tool starts. RELOPS_CALLER_CWD is always exported.
--offlineNo network. Cached refs and objects only, labeled as cached.
--verboseCache and resolution diagnostics on stderr.

Exit codes: 1 launcher error · 2 usage error · otherwise the tool's own status (128 + signal if it was killed).

03honest limits

What relops is not.

  • Worktrees isolate repo-local writes only. Home-dir caches, credentials and external services are shared.
  • Pushed commits only. Your uncommitted local changes are not shared.
  • It does not install dependencies, run setup hooks, or init submodules and LFS.
  • A branch can move. A full SHA cannot. Share a SHA when the review is of exact code.
  • v1 is SSH-only, mozilla-platform-ops only, macOS and Linux only.

Files you want to keep must be written outside the temporary checkout. It is deleted when the tool exits.

05roadmap

Placeholders, not promises.

  1. v1“Try this tool on my branch.” Explicit repo/path, refs, shared cache, per-run checkout, offline mode, provenance.
  2. v1.1“Find and run our usual tools.” Git-backed registry, aliases, list / info, visible revision policy.
  3. v1.2“Install and update easily.” Verified hosting, release manifest, safe self-update.
  4. v1.3“Keep everyday use convenient.” Cache pruning, shell completion, optional TTL.
  5. later“Add a shared tool with less ceremony.” Registry edits that prepare reviewed Git changes.
